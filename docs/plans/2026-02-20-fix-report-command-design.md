# Design: `/fix-report` Command + Review Step 7 Simplification

**Date:** 2026-02-20
**Plugin:** code-review
**Version:** 1.5.0 → 1.6.0

## Problem

After saving a code review report, the reviewer asks the user which issues to fix. When there are more than 4 issues, the LLM presents grouped options (e.g., "P1 only (1-4)", "All fixable (1-8)") instead of a granular per-issue checklist. The user expects individual issue selection.

Additionally, the fix flow is tightly coupled to the review session — you can't return to fix issues later.

## Solution

1. **New command `/fix-report <path>`** — reads a saved review report, extracts unfixed issues, presents them as a paginated multiSelect checklist, and runs fix-auto for each selected issue.
2. **Simplified Step 7 in review.md** — review no longer handles fixing. It displays a suggestion to use `/fix-report <path>` or `/fix <issue>`.
3. **Report as living document** — after each successful fix, the report file is updated with a `**Status:**` field. Fixed issues are excluded from future `/fix-report` runs.

## Design Details

### Changes to review.md (Step 7)

Current Step 7 (lines 396-475) — full fix flow with Yes/No, checklist, auto-fix, summary — is replaced with a short post-review guidance:

- If issues found AND report saved: suggest `/fix-report <path>` and `/fix <issue>`
- If issues found but report NOT saved: suggest `/fix <issue>`, note that `/fix-report` requires a saved report
- If no issues found: "Review complete"

Task 8 renamed from "Fix selected issues" to "Display post-review guidance".

Final Verification Checklist "Post-Review Actions" simplified to:
- User asked whether to save review
- Review saved to `docs/reviews/` (if requested)
- Post-review guidance displayed

### New command: `/fix-report`

**Input:** path to a saved review report (markdown file generated by `/review`)

**Step 1: Parse report**

Read the file, find sections matching `### [SEVERITY] Title`. For each section, check if `**Status:** ✅ Fixed` or `**Status:** ⚠️ Partially Fixed` exists — if so, skip (already handled). Collect unfixed issues with their full blocks.

**Step 2: Early exit**

- All issues fixed: "All issues in this report have been fixed. Nothing to do."
- No recognizable issues: "No issues found in this report. Make sure the file was generated by `/review`."

**Step 3: Paginated checklist (pages of 4)**

Issues sorted by severity (CRITICAL → HIGH → MEDIUM → LOW). Presented via AskUserQuestion with multiSelect, 4 options per page. Each option:
- label: `[SEVERITY] Short title`
- description: `path/to/file.py:line — brief problem description`

Each page after the first includes a "Skip remaining" option. After all pages (or skip), the collected selections proceed to fixing.

**Step 4: Sequential fix**

For each selected issue, invoke fix-auto subagent:
```
Task(
  subagent_type: "code-review:fix-auto",
  run_in_background: false,
  prompt: <full issue block from report>
)
```

**Step 5: Mark in report**

After each fix, edit the report file to add a `**Status:**` field immediately after the issue's `###` title line:

- Fixed: `**Status:** ✅ Fixed (YYYY-MM-DD)`
- Partially Fixed: `**Status:** ⚠️ Partially Fixed (YYYY-MM-DD)`
- Failed: no status added (issue remains unfixed for next run)

**Step 6: Summary**

Display fix summary table with counts, then note which report file was updated.
