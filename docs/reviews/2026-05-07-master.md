## HIGH

### [HIGH] DOC-001: `fix-auto` agent omits `Testing` category — QA fixes silently under-verified `[verified]`
**Status:** ✅ Fixed (2026-05-07)

**ID:** DOC-001
**Location:** `plugins/code-review/agents/fix-auto.md:40` (Category enum) and `:172-182` (verification table)
**Category:** Documentation
**Effort:** trivial

**Problem:**
`fix-auto` is the autonomous subagent dispatched by `/fix-report` Step 3.1 for every selected issue, including QA issues with `**Category:** Testing`. Two embedded tables in this agent file are stale:

1. Line 40 Category pattern: `Security|Performance|Architecture|Maintainability|Documentation` — `Testing` is missing. `fix.md:149` correctly includes it.
2. Lines 172-182 verification-tools table has rows for the five other categories — `Category = Testing` is missing. `fix.md:350` correctly includes it.

The design spec (`docs/superpowers/specs/2026-05-07-qa-code-review-synergy-design.md:55`) explicitly listed `fix-auto.md` as "format-agnostic, no changes needed" — that assumption was wrong because these tables encode parser/router behavior.

**Impact:** Every `/fix QA-NNN` going through `/fix-report` lands in `fix-auto`. The Category enum says "Required: Yes" — an unrecognized value can cause the agent to ask the user to re-supply the field, or fall through to no rule. Even in the permissive case the verification table has no Testing row, so QA fixes are committed with weaker verification than other categories (effectively lint-only). Symmetric inconsistency with `fix.md:350` is a bug — the same pattern was updated in one file and not the other.

**Remediation:**

```diff
- | Category | `**Category:** Security\|Performance\|Architecture\|Maintainability\|Documentation` | Yes |
+ | Category | `**Category:** Security\|Performance\|Architecture\|Maintainability\|Documentation\|Testing` | Yes |
```

Add to the verification-tools table after the Documentation row:

```
| Category = Testing | Linter + run any test file matching the modified source; re-run the QA scenario manually if feasible |
```

Bump `code-review` to 1.13.1 (PATCH) and propagate to the four parity locations.
