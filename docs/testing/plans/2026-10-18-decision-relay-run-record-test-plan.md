**Relay protocol.** These checks apply to rows 8, 10 and 12, where a dispatching session continues the relaying session.

- **Task text and standing answers are not answers.** A decision, approval or consent in the task text, a message that arrived before the request, a standing answer and a line quoting another request's ID are never acted on (plugins/code-review/skills/decision-gate/SKILL.md:971-975; plugins/code-review/commands/fix-all.md:643). Request 1 goes out anyway, and the replay check has not run before the offer is accepted, so a live automatic decision is neither revoked nor replayed (plugins/code-review/skills/decision-gate/SKILL.md:986). STANDING covers it — terminal agent session.
- **A message without the current Relay-ID is not a reply.** The turn ends again with the same request block, unchanged, after the summary block (plugins/code-review/skills/decision-gate/SKILL.md:977, 1025). Only the first message holding a line with the current Relay-ID counts, later lines for that ID are ignored, and an item left out or answered with an unlisted option stays unanswered (plugins/code-review/skills/decision-gate/SKILL.md:977). RELAY-PROTOCOL messages (1), (2) and (4) cover it — terminal agent session.
- **The offer.** Request 1's `### offer` carries Step 5.2's question `Resolve <N> findings requiring your decision now? <N> findings to analyse, in <B> batch(es) of at most 8.` with `Yes — resolve <N>` and `No — leave them` (plugins/code-review/skills/decision-gate/SKILL.md:988; plugins/code-review/commands/fix-all.md:635-640). Any other answer, or none, ends the stage with nothing written: the summary's rows read `open — offer declined`, or `open — no relayed answer` when the offer was left out, followed by Step 5.3's `Left <N> findings for later.` line (plugins/code-review/skills/decision-gate/SKILL.md:993, 1025; plugins/code-review/commands/fix-all.md:651). STANDING covers a declined offer; no planned run leaves the offer out — terminal agent session.
- **Location items.** Each location-less finding gets `### location <ID>` with `<ID> (<title>) has no usable location: <the Location field as written>. Reply with the path:line to analyse it at, or skip.` and the options `<path:line>` (typed) and `skip` (plugins/code-review/skills/decision-gate/SKILL.md:990). A relayed `path:line` is validated once and never re-asked. A failure, `skip` or no answer makes a declined target: Decided by `—`, Outcome `failed — no target`, and no request 2 item, snapshot or dispatch (plugins/code-review/skills/decision-gate/SKILL.md:128, 997, 1001). RELAY-PROTOCOL message (3) covers the unanswered item; no planned run relays an invalid `path:line` — terminal agent session.
- **Decide items.** Each `### decide <ID>` shows *The render, stated exactly* and offers `A`, `B`, `skip` and the reject option, never `other…`, leaving out `B` or the reject option where the interactive call would (plugins/code-review/skills/decision-gate/SKILL.md:370, 1003). Without a `Rejection candidate` the reject option is `reject — <one-line reason>`; with one it is `reject`, which confirms the prefilled reason; every decide item ends with `To reject with your own reason, type: reject — <one-line reason>.` (plugins/code-review/skills/decision-gate/SKILL.md:1004). A stalled finding is not analysed: its item shows both retired resolutions and offers `skip` and `reject — <one-line reason>` (plugins/code-review/skills/decision-gate/SKILL.md:1006). A degraded finding shows its raw block, the `code analysis unavailable` note and the restated alternatives (plugins/code-review/skills/decision-gate/SKILL.md:1005). RELAY and STALLED cover the first three; the degraded path has no planned run, because an analyst failure cannot be induced from a fixture (docs/plans/2026-10-16-decision-run-record-relay.md:516) — terminal agent session.
- **Answers that write nothing, or only a status.** No answer leaves `open — no relayed answer`. A typed answer outside the two named forms leaves `open — typed answer — decide it in an interactive run`. `skip` writes nothing and reads Decided by `you (relayed)`, Outcome `skip`. `reject`, for a stalled finding too, writes only `**Status:** 🚫 Rejected (YYYY-MM-DD) — <reason>`, and a rejection with an empty reason leaves `open — no relayed answer` (plugins/code-review/skills/decision-gate/SKILL.md:728, 977, 1004, 1011-1015). A relayed rejection's Verification is `evidence re-run` when a supported candidate backed it and `unverified` otherwise (plugins/code-review/skills/decision-gate/SKILL.md:725). RELAY (typed reason), STALLED (empty reason, stalled rejection) and RELAY-PROTOCOL (`skip`) cover these; no planned run relays a typed answer — terminal agent session.
- **`A` or `B`.** Before writing, the gate checks that it still holds the proposal, that a proposal snapshot of the chosen alternative exists with no `unpinnable` entry, and that the recomputed `**Decision-pin:**` value equals that snapshot. A failure leaves `open — analysis no longer held`, `open — no snapshot — decide it in an interactive run` or `open — proposal changed while waiting`, with nothing written (plugins/code-review/skills/decision-gate/SKILL.md:1016-1019). Otherwise stage 2's closed list of writes is made with provenance `relayed`, so the block gains `**Decision:** <label> — <resolution> [relayed, <date>…]`, and stages 3 to 4 dispatch, verify and grade it (plugins/code-review/skills/decision-gate/SKILL.md:750, 1021, 1023). RELAY (`A`), RELAY-STALE (an edit to a pinned file) and RELAY-GUARD DOC-003 (the unpinnable `notes/$draft.md`) cover these; no planned run loses the proposal — terminal agent session.
- **Report snapshot.** Every block a request concerns is hashed when the request goes out and again on the reply, before any answer is acted on. A changed or missing block leaves `open — report changed while waiting`, with nothing written and no further item, analysis or dispatch; a snapshot that could not be taken leaves `open — no snapshot — decide it in an interactive run` (plugins/code-review/skills/decision-gate/SKILL.md:979). RELAY-GUARD DOC-001 (a status inserted) and DOC-002 (an edited `**Problem:**`) cover it — terminal agent session.
- **Out-of-boundary checks.** `### checks <ID>` appears only where `A` or `B` holds checks outside the execution boundary. It lists each command's exact text per alternative and the cost of declining, with the options `Run them` and `Don't run` (plugins/code-review/skills/decision-gate/SKILL.md:1007). Only a `checks <ID>: Run them` line in the reply approves, and only the commands listed for the chosen alternative; unanswered or `Don't run` makes them checks that cannot be run (plugins/code-review/skills/decision-gate/SKILL.md:506, 510, 1021). The finding's `**Verification:**` then reads `advisory — <checks run>; <N> not run: <check text>` when some checks ran, and the finding takes stage 4's fourth case when none ran (plugins/code-review/skills/decision-gate/SKILL.md:569-570). RELAY-CHECKS covers both answers when request 2 carries a `checks` item for each finding — terminal agent session.
- **No second pass.** A finding the pin comparison sets aside keeps its supersession rewrite and stays `open — set aside before dispatch` for the next run (plugins/code-review/skills/decision-gate/SKILL.md:460, 723, 1023). No planned run covers it — terminal agent session.
- **Relay-ID.** One token per gate invocation, from `openssl rand -hex 4` or `python3 -c 'import secrets; print(secrets.token_hex(4))'`, gives `RLY-<token>-1` and `RLY-<token>-2`. Anything but 8 hexadecimal characters prints `Relay unavailable: <error>; <N> findings stay open.`, writes nothing and ends the stage, with rows `open — relay unavailable` (plugins/code-review/skills/decision-gate/SKILL.md:969, 1025). RELAY checks for a single token call; no planned run covers the failure — terminal agent session.
- **Request block.** `## Decision relay request <Relay-ID>`, then `Report: <report path>. <N> finding(s) wait for the owner.`, the instruction paragraph with the reply-line form `<Relay-ID> <item>: <option exactly as listed, any placeholder filled in>`, `Items you leave out stay open.`, and per item a `### <item>` heading, its question and an `Options:` line. Nothing follows the block (plugins/code-review/skills/decision-gate/SKILL.md:1027-1041). RELAY and PRINT cover it — terminal agent session.
- **Composites.** The dissolve question is not relayed. It fails closed, so proposed composites are dropped and persisted ones are dissolved for the run, with nothing written (plugins/code-review/skills/decision-gate/SKILL.md:967; plugins/code-review/commands/fix-all.md:353). No planned run is built around a composite — terminal agent session.
- **Claude Code relay.** `/fix-all` pre-approves neither `openssl` nor `python3 -c` (plugins/code-review/commands/fix-all.md:2), so a relaying Claude Code session may raise a permission prompt for the token, and a denied prompt takes the `Relay unavailable` path (plugins/code-review/skills/decision-gate/SKILL.md:969). The run matrix has no Claude Code relay run (docs/plans/2026-10-16-decision-run-record-relay.md:517) — terminal agent session.
- **OMP preamble.** The OMP edition tells a subagent to choose the most likely option (plugins-omp/code-review/commands/fix-all.md:15). Step 5.2 and Relay mode override that rule for the offer and the decision stage (plugins/code-review/commands/fix-all.md:643; plugins/code-review/skills/decision-gate/SKILL.md:967). Every OMP relay run covers it — terminal agent session.
- **Several ask calls.** The request header lets the dispatching session ask in as many calls as its ask tool needs, then reply once (plugins/code-review/skills/decision-gate/SKILL.md:1034). OMP's `ask` takes any number of questions, so no planned run splits a request (docs/plans/2026-10-16-decision-run-record-relay.md:518) — terminal agent session.
